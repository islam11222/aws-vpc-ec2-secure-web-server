What I implemented

These components were configured and validated using the AWS Management Console and, for troubleshooting, EC2 Instance Connect.

01 · Network

Custom VPC & routing

Created a VPC with four subnets in two AZs, an Internet Gateway, and dedicated public/private route tables. Verified public default routing and private local-only routing.

02 · Access

Security group

Opened HTTP port 80 to public IPv4 traffic. Limited SSH port 22 to an administrator IP and the EC2 Instance Connect service prefix list.

03 · Compute

EC2 + encrypted storage

Launched an Amazon Linux 2023 t3.micro in public subnet 1, with an 8 GiB gp3 EBS root volume encrypted using the AWS-managed EBS key.

Troubleshooting: from failure to working HTTP

A useful part of this project was diagnosing a failed first-boot configuration instead of assuming an EC2 instance was broken.

1
Symptom

The public IP initially returned a browser connection error even though the EC2 instance had passed its system, instance, and EBS status checks.

2
Investigated AWS networking

Checked security-group rules, Internet Gateway routing, network ACL inbound/outbound rules and subnet associations. Those checks did not identify an obvious traffic block.

3
Found initialization failure

EC2 System Log reported that the cloud-init scripts-user module failed. The precise failed command was not established from the available log.

4
Recovered the web server

Connected through EC2 Instance Connect, installed Apache using the package manager, enabled the service, deployed a simple HTML file, and confirmed HTTP/1.1 200 OK.

5
Verified public accessibility

Opened the EC2 public IPv4 URL in a browser and confirmed that the demo page rendered successfully.
